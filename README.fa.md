# Project Foundation

**پروژه‌ای بسازید که جلسهٔ بعدی هوش مصنوعی بتواند مسیرش را ادامه دهد.**

[English](README.md) · [نصب](docs/installation.md) · [مثال](docs/example.md) · [سازگاری](docs/compatibility.md)

این اسکیل برای شروع منظم پروژه و ادامهٔ قابل‌پیگیری آن طراحی شده است. ابتدا پروژه را بررسی می‌کند، تصمیم‌های مهم را از شما می‌پرسد و دو فایل را می‌سازد یا با نسخه‌های موجود ادغام می‌کند:

| فایل | کاربرد |
| --- | --- |
| `AGENTS.md` | قوانین ثابت، تکنولوژی، پوشه‌بندی، اسکیل‌های تأییدشده، بک‌آپ، امنیت، UI/UX و معیارهای کیفیت |
| `PROJECT_STATUS.md` | وضعیت فعلی، فازها و وظایف، تصمیم‌ها، تاریخچه، نتایج بررسی‌ها، موانع و قدم بعدی |

پیش از نوشتن مستندات، زبان را با پیش‌فرض پیشنهادی انگلیسی می‌پرسد. برای بک‌آپ، گزینه‌های لوکال، Git، ترکیبی، روش دلخواه یا انصراف صریح ارائه می‌کند. اسکیل‌های مناسب پروژه را پیشنهاد می‌دهد و شما می‌توانید آن‌ها را تأیید، اضافه یا حذف کنید. پاسخ‌های ثبت‌شده در هر جلسه دوباره پرسیده نمی‌شوند.

## شروع سریع در Codex

```bash
git clone https://github.com/alidavodidev-lgtm/project-foundation.git ~/.agents/skills/project-foundation
```

سپس در چت:

```text
از $project-foundation استفاده کن و پیش از پیاده‌سازی، این پروژه را آماده کن.
```

برای Windows و ابزارهای دیگر، [راهنمای نصب](docs/installation.md) را بخوانید. مسیر نصب و نحوهٔ فراخوانی بین کلاینت‌ها متفاوت است.

## ادامهٔ پروژه و مدیریت توکن

در جلسه‌های بعد، ایجنت ابتدا قواعد و خلاصهٔ وضعیت فعلی را می‌خواند. تاریخچهٔ قدیمی با لینک بایگانی می‌شود؛ جزئیات لازم حفظ می‌شوند، اما لازم نیست تمام سابقه در هر جلسه بارگذاری شود. اسکیل‌ها و منابع فقط هنگام نیاز خوانده می‌شوند. میزان مشخصی از صرفه‌جویی توکن تضمین نمی‌شود.

فایل‌های دیگری مثل معماری، تصمیم‌های فنی و راهنمای بازیابی فقط در صورت نیاز ساخته می‌شوند. این اسکیل ساخت پروژه، انتشار یا نصب ابزارهای اضافی را خارج از درخواست شما مجاز نمی‌کند.

## سازگاری و محدودیت

بسته بر پایهٔ استاندارد باز Agent Skills است. مسیرهای نصب Codex، Claude Code، Google Antigravity، Gemini CLI، Cursor و GitHub Copilot مستند شده‌اند. پشتیبانی فرمت با آزمایش عملی تمام نسخه‌ها متفاوت است؛ [وضعیت اعتبارسنجی](docs/validation.md) شفاف ثبت می‌شود.

نسخهٔ اصلی فقط Markdown است و API Key یا سرور MCP لازم ندارد. ایجنت باید امکان خواندن و تغییر فایل‌های پروژه را داشته باشد. قواعد اسکیل جایگزین محدودیت‌های اجرایی، زمان‌بند بک‌آپ یا بررسی تخصصی امنیت نیستند.

پیشنهادها و گزارش تجربهٔ واقعی را در [Issues](https://github.com/alidavodidev-lgtm/project-foundation/issues) ثبت کنید. اگر برایتان مفید بود، ستاره دادن به دیده‌شدن پروژه کمک می‌کند.
